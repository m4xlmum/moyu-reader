# 验证工具

`spike/` 下有几个一次性工具，用于在真机上复核关键行为：

```bash
npx electron spike/index.js
```

自行截屏并比对像素，验证透明窗口的合成行为（`setBackgroundColor` 是否生效、
`setOpacity` 与 `transparent` 能否共存、`setShape` 是否可裁剪等），
结论见 [spike-findings.md](spike-findings.md)。

```bash
npx electron spike/capture.js <输出路径>
```

把当前屏幕截图写入 PNG，用于无法目视时检查渲染结果。

```bash
npx electron spike/minsize.js
```

探窗口能被缩到多小：给一个挂在不显示窗口上的最小尺寸试探器，逐档尝试
`setBounds` 再读回实际矩形。悬浮球直径的下限就是这么量出来的。

```bash
npx electron spike/destroyed.js
```

探「窗口销毁之后还能碰什么」：`'closed'` 事件是在窗口已经销毁之后才触发的，
此时 `win.id` 与 `win.getBounds()` 都会抛 `Object has been destroyed`。退出时
弹的那个主进程错误框就是从这里来的，脚本里另附一段走完整 `app.quit()` 的
正确写法作对照。

```bash
npx electron spike/ownpage-bg.js
```

探「给网页注入的透明样式会不会打到自家页面」：注入前后各读一次系统设置与起始页
`html` / `body` / 各自底板层的实测底色。注入的是 user origin 的 `!important`，
压得过作者样式表，写在这两层上的底色是挡不住的——所以底板另画一层
（起始页 `.page`、系统设置 `.layout`），打开系统设置时背景全透明就是这么来的。

```bash
npx electron spike/dragTicks.js
```

量两件与拖动流畅度有关的事：`setInterval` 在 Windows 上**实际**多久触发一次
（请求 16ms 得到 p50 30.2ms，请求 8ms 得到 15.1ms——间隔被向上取整到系统时钟
滴答的整数倍），以及单次 `setPosition` 要花多久（p50 2.5ms）。拖动间隔
`DRAG_TICK_MS` 就是按这份数据定的。隐藏窗口里量到的只是**下界**：真实拖动时
窗口还要参与合成，只会更慢。

```bash
npx electron spike/resize.js
```

探「四边四角拖一下，窗口该变成哪一块」：先用 esbuild 把真的 `src/main/services/geometry.ts`
打成 CJS 再 `require`（验真的，不验抄本），断言 `resizeRect` 的那几条不变量——
32 组拖法（八条边 × 四种位移）结果**恒为 16:9**（±1px）、被拖边对面那条边一动不动、
上下限被尊重、拖角时相对变化更大的那一轴说了算；再开一扇隐藏的真窗口，
按算出来的矩形 `setBounds` 并读回比对，顺带走一遍「工作区整块能不能被一次
`setBounds` 摆出来」——最大化就靠它。

```bash
npx electron spike/window-max.js
```

探最大化与还原，起的是**真的** `WindowController`（配置写在临时目录里，不碰用户的
那一份）：create 之后窗口就是配置里那块 16:9；最大化之后窗口正好是工作区、
`getRuntime()` 报 `maximized`、两栏与地址栏一起让位、正文占满整窗；界面层缩成
右上角那一小块，并且**被抬到正文之上**——否则还原键与球会被网页整个盖住，
最大化之后窗口就没有出口了。

```bash
npx electron spike/vieworder.js
```

探子视图的叠放次序：把一个**已经在场的**子视图重新 `addChildView`，它会被重排到
最上层（不是多出一份）；抬上 / 让回交替十次，子视图个数与顺序都不漂。
另外记一条环境事实：**隐藏窗口里取不到视图快照**（`capturePage()` 抛
`UnknownVizError`），因此这个探针只断言顺序与几何，不报像素。

```bash
npx electron spike/fullscreen.js <enter|exit|ownership|restore|roundtrip|collapse|control>
```

探「点网页里视频的全屏键，软件窗口跟不跟得上」，起的是**真的** `WindowController`
与**真的** `TabManager`（配置写临时目录、会话用内存分区）。**一问一个进程**，
跑法见文件头部：

```bash
for s in enter exit ownership restore roundtrip collapse control; do
  npx electron spike/fullscreen.js $s
done
```

`enter` 那一支问的是：窗口是被页面那一串事件推着变的吗？——探针里没有谁直接调
`maximize()`，窗口仍然铺满了工作区、`runtime.maximized` 变成 true、正文矩形等于整窗，
才叫接线通了。`control` 那一支是对照组，量出 `disableHtmlFullscreenWindowResize`
这个开关确实管用：不关掉的话 Chromium 会自己把窗口铺到**整块显示器**
（本机 1920×1080，连任务栏一起盖住），而我们要的是工作区 1920×1032。

```bash
npx electron spike/fullscreen-cycles.js <plain|real|surgery|surgeryDefer|relayout|reorder|shown>
```

上一个是给产品用的，这一个给「分清环境的脾气与产品的毛病」用：一扇最小、可控的
窗口，一样一样地把变量摘出来（窗口配置 / 回调里改窗口尺寸 / 重排子视图 / 推迟一个
tick / 窗口显示没显示），连续走三趟全屏进出，看哪一趟起就坏了。结论写在文件头部，
也并进了 [spike-findings.md](spike-findings.md) 的 Q21–Q24。

```bash
npx electron spike/media-pause.js
```

探「窗口没露出来时，网页里正在播的音视频会不会停」，起的是**真的** `WindowController`
与**真的** `TabManager`，`onVisibilityChange` 那一条接线与 `src/main/index.ts` 一字不差
（这一问验的就是这条线：收起 / 进托盘 / 最小化 → 暂停，回到展开态 → 恢复）。

页面里是**真在播的媒体**，不是摆样子：探针在 Node 里现生成一段 8kHz PCM 的 WAV
（Chromium 原生就认，不依赖任何编解码器），`loop` 起来，所以 `paused === false` 是真的；
每一问动手之前先断言「确实在播」，前提不成立就照实报「否」并写明是哪一条前提，
而不是给一个好看的通过。场上三个元素各有用处——正在播的主媒体、**由用户自己按停**
的那一个（展开时不该被我们放起来），以及一个 `data:` iframe 里的播放器（跨源，
顶层脚本够不到，只有主进程按帧走才够得着，真实网站的嵌入播放器就是这个样子）。
另有一张**后台标签页**同样在播：收起时只停当前那一页的话，声音还在响。
最后两问盯住另外两半——静音（Web Audio 之类暂停不到的靠它兜底）、以及
把这个开关关掉之后收起时**什么都不该动**。

```bash
npx electron spike/popover-focus.js
```

探「弹出面板该在什么时候自己收起」，起的是**真的** `PopoverWindowService`。
起因是一句反馈——「标签页点击之后的弹框是分离的，当我再次点击其他内容失去焦点的时候，
这个标签页的弹框并不会随之关闭」：根子在一行上，面板原先用 `showInactive()` 摆出来，
焦点一直留在主窗口，于是「用户点了别处」面板根本收不到（`blur` 永不触发）。
这一问因此盯住整条链子：摆出来走的是 `show()`（拿焦点）而不是 `showInactive()`、
在场期间自动收起被挂起、失焦即收起且**不抢焦点**、失焦收起后紧接着的**同一次点击的
第二半**不把它重开（那颗键仍旧是开关）、上一边那块面板迟到的 `blur` / `closed`
不许误关新面板、只有用户自己在面板里选完东西那条路才把焦点还回主窗口。

**它不动用户的桌面**：每建一扇面板窗口，立刻挪到所有显示器之外并设成不可聚焦——
于是它既不出现、也不抢焦点。唯一被替换掉的恰是「`show()` 会不会拿到焦点」这个 OS 行为，
而那一条改从调用记录上问（面板窗口的 `show` 被换成一个记账的壳）；焦点那一步的实物
确认留给真机。另有一条坑记在文件里：面板在探针里往往是场上唯一一扇窗，而 Electron
默认最后一扇窗关掉就退出进程——第一问刚过、失焦那一步一收面板，整个探针就悄没声地
退了（退出码还是 0），因此那里挂了一条空的 `window-all-closed`。

```bash
npx electron spike/theme-chrome.js
```

探「主题管到整个界面之后，四份文档在三套主题下各自长什么样」。四份文档各开一扇隐藏
窗口加载编译好的那几份 `html`，三套主题各跑一遍，十二问：

- **默认零回归**：纸白下界面里那 26 条 `--moyu-*` 的计算值，与改动前写死在样式表里的
  值**逐条相同**——默认外观一个像素都不许变，这一条是整件事的前提
- 四份文档 × 三套主题都真的换了色（防止某一段没生效、悄悄退回默认）
- 磷绿下圆角全为 `0px`、字体含 `Cascadia Mono`，且**逐元素**验一遍（写死的圆角
  不会跟着变量归零，地址栏那个切换键与标签格就是这么被找出来的）
- 「背景透明度」那条滑块仍然管用：把它设成 0.4，面色的 alpha 跟着变
- **透明中部没被弄坏**（这一问最要紧）：三套主题下 `.root` / `.main-col` / `.middle`
  / `.spacer` 全是 `rgba(0, 0, 0, 0)`，且界面文档里**没有任何**铺满视口的
  `body::after`——终端世界的扫描线层不许越界到界面里来
- 对比度，以及设置页的可读性：逐对量「字压在哪个面上、多少比」，
  按 WCAG 三比一（大字）／四点五比一（正文）判，量出来最紧的一处是纸白下的
  选中按钮 4.67:1。写死的浅色面板、UA 样式表给按钮的那个黑，都是这么现形的
- **更新提示条也站得住**（三问，单独加载——那一行只在有新版时才占版面，
  一直挂着会让上面那几条基准漂移）：它画在自己那一行上（三套主题下都是 912×30，
  正落在顶栏之下、右栏之左），**底色 / 字色 / 强调色 / 圆角逐条取自当前主题的令牌**
  （写死一个白底的话，纸白下看着完全正常，夜与磷绿下当场就是一块白条），
  三套主题的行底色必须两两不同；`.spacer` 仍是逐像素透明，也就是这一行**没有把
  底下那一块染上色**；下载中那条 2px 的进度线画在这一行的下沿，
  **行高不变**——条的高度是主进程算进版面里的，这里改高一点网页就要被压住一条

```bash
npx electron spike/update-check.js
```

探「自动检查更新」这条路上的每一段：查、比版本、下载、校验、装。esbuild 把真的
`updateService.ts` / `configStore.ts` / `version.ts` 打成一包再 `require`（验真的，
不验抄本），配置写在临时目录里，本机起一只 `http.createServer` 当假 GitHub——**它自己
记着收到过几次请求**，所以「开关关掉就不许联网」是数出来的，不是看返回值。十二问：

- **先钉死「不行的那条路」**：feed 供同版本 → 不提示；feed 指向一个已经关掉的端口 →
  `error`，且窗口里**一条提示都不冒**（不是「反正没显示」，而是 `setNoticeVisible`
  替身收到的全是 false）。隐身软件不该因为一次网络抖动在屏幕上冒出东西来
- **版本比较逐条**：`1.0.0/1.1.0`、`v1.0.1` 的 `v`、两段的 `1.0`、`1.0.0.0`、
  `1.1.0-beta` 低于 `1.1.0`、`abc` 与空串——认不出来的一律**不判为更新**
  （宁可漏报，不可误报）
- **下载 + 校验**：文件真的落在盘上、sha512 与 `latest.yml` 里的一致、没有留下
  `.part`，进度广播**不超过 101 次**（0–100 各一次，不许刷屏）、单调不减、最后一次是 100
- **篡改 sha512** → `error`，且那个文件与半截的 `.part` **都没有留在盘上**
  ——一个来路不明的东西不许停在马上就要被执行的位置
- **网络不通**（feed 指向关掉的端口）立刻 `error`；**只接不答的服务器** 15 秒收场
  （`ClientRequest` 在 Electron 里没有 `setTimeout`，见 Q34）
- **开关关掉就不许联网**：`autoCheck: false` 时自动那一次**一次请求都不发**，
  而手动那一次照发
- **忽略的版本不再提示**：忽略之后 `available` 仍在（设置页看得见）、提示条不出；
  换个版本又出来；`ignore(null)` 能撤销，并且**落盘**——换一个新的 `ConfigStore`
  从同一个目录读回来才算数
- **没校验通过不许起安装程序**：`idle` / `available` / 下载一半时调 `install()`，
  spawn 替身**一次都没被调用**；`ready` 之后恰好一次，路径是那个 exe，
  无实参、`detached`、`stdio: 'ignore'`，随后 quit 恰好一次
- **已经下过的那一份会被认出来**：再查一次直接 `ready`，且**没有第二次下载请求**
- **真实的那一份 `release/latest.yml`** 解析得出来：url、sha512、size 与盘上那个
  1.0.0 的 exe 逐项对得上（喂给它的是真构建产物，不是手写的样例）

| `--bg 0.35` | 把界面底板透明度设成这个值。看的是「底板淡了、字没淡」 |
| `--maximized` | 已最大化：没有两栏也没有正文，只在右上角那一小块里浮着「还原键 + 球」。不给尺寸时按那一小块的尺寸开窗（80×48） |
| `--notice 1.1.0` | 界面里多出更新提示条那一行（地址栏与网页之间）。`--notice-phase ready\|downloading\|error` 换那一态，`--notice-percent 42` 给下载中那条进度线一个长度，`--notice-message` 给失败那一句原因。不给 `--notice` 就一条提示都没有——那正是「没有新版本」的正常样子 |
| `--ball-icon <id>` | 球面上画哪一枚内置图标（八枚之一：书页 / 眯眼 / 摸鱼 / 咖啡 / 月亮 / 猫 / 代码 / 耳机），或 `custom` |
| `--ball-image <路径>` | 把这张本地图当作「用户上传过的那张自定义图标」 |
| `--ball-fit cover\|glyph` | 自定义图标落进球里的方式：铺满球面 / 中央图案 |
| `--drag-probe` | 逐个位置按一下，问「这里按下去起没起拖动」，顺带数一遍缩放手柄 |
| `--tabs 2` | 顶栏只留前 2 个标签页：标签条放得下那一态。5 个标签的标题都长（每格 180px），960 宽的窗口只放得下两格，因此「放得下」那一态得靠少给几张才摆得出来 |
| `--screen home\|settings` | 界面停在起始页 / 系统设置上那一态：没有哪一格标签高亮，那颗键自己亮着，地址栏开关上写着这一屏的名字（`--tabs` 照旧管标签条里有几张网页） |
| `--click-tab 2` | 点第 2 格标签，再截一张。看的是「点得动、切换真的有反应」 |
| `--click-rail-pause` | 点右栏最上面那格开关，再截一张。按 title 定位到那一格，报出**配置改没改、高亮跟没跟着改、旁边的项有没有被带坏**，并另存一张 `-railpause` 对照（开/关两态一眼看得出） |
| `--click-screen` | 依次点「设置 → 再点一次 → 起始页键 → 再点一次」，每步读一次标签状态。看的是**进出那两屏的往返**：进去之后标签条上是不是没有哪一格高亮、那格自己亮没亮、地址栏开关上写的是不是那一屏的名字，再点一次是不是回到刚才那张网页（两步各截一张） |
| `--resize 1100x700` | 截完改窗口尺寸再截一张。标签条让位与回归都靠这一步走一遍 |
| `--width 620 --height 420` | 换个窗口尺寸，用来试窄窗口与矮窗口下的版面 |
| `--desktop dark` | 界面背后垫一层模拟桌面（截宣传图用）。不给值就是浅色桌面，也可直接给一段 CSS 渐变 |
| `--alpha` | 窗口用透明底色截，PNG 里保住透明通道——界面底板、球、弹出面板那几张都要它 |
| `--out spike/out/readme` | 产物写到别的目录。README 的图与平时核对的那批分开存，不互相覆盖 |

JSON 里的 `rightButtons` 是顶栏右侧那排按钮的顺序与坐标（`topIcons` 里带各自的
高亮与实测颜色：手机跟着当前标签页的 `uaMode`，置顶跟着 `window.alwaysOnTop`），
`railButtons` 是右栏里剩下的功能，`sliders` / `stackScroll` 用来核对新加的
背景透明度滑块有没有把右栏撑出可视区，`themePanel` / `themeItem` 用来核对主题
列表有没有被折进滚动区。`surfaces` 是底板透明度那一对关系的实测值——
`alpha` 是界面根上那个变量，`bar` 是顶栏的实测底色（应当带上这个 alpha），
`ink` 是图标与文字的实测颜色（必须是不带 alpha 的实色，拉到 0 也要看得见）。
顶栏的 `stripFits` / `tabBoxes` / `lastTabOverflow` / `fallback` 几项是给标签条用的：
让位了没有、每一格的宽度、最后一格有没有被容器啃掉一条边。`tabBoxes` 里的
`closeVisible` 走的是 `checkVisibility`，算的是「真的画出来了没有」而不是
「这一格自己写着什么」——让位时整条是隐藏的，两者给的答案不一样（见 [架构要点](architecture.md) 第 8 条）。
`--home --themes` 的主题名单是**从页面上读的**（`.theme-menu .panel .chips`），
不在脚本里另抄一份；换主题走的是**真实那条路**（点菜单项 → 写配置 → 广播 → 重新渲染），
因此它验的是「主题真的换了形态」，而不只是换了几个变量。

`--drag-probe` 是给拖动与缩放用的：在一组**有名有姓**的位置上（顶栏留白、两屏那两颗键、
两屏键与导航组之间的缝、导航组与
地址栏之间的缝、标签条右侧那一大块、标签格、手机 / 置顶 / 最大化 / 最小化按钮、
悬浮球、右栏的分隔线与格子之间的缝、滑块的小字与轨道，再加上更新提示条上的
文字、主按钮与忽略键——后三处要 `--notice` 才有，不给就报「这一点算不出来」）
各派发一次
`pointerdown` + `pointerup`，再读假桥里的计数，逐个报出「拖 / 不拖」以及那一点上
究竟是哪个元素；八条缩放手柄也逐个按一遍，报出「按下去起的是哪条边的缩放」。
它问的是界面自己，不是代码：上一版整条顶栏与右栏都被 no-drag 的子元素铺满、
只剩悬浮球拖得动，而这件事从代码与截图上都看不出来。
判据是 `DRAG_BAD` 必须是空的——**一个控件都不能被手柄或拖拽抢走它的点击**。
合成事件不会合成出 `click`，因此按在按钮上的那些点没有副作用。

```bash
npx electron spike/ball-crop.js
```

探裁剪弹窗点「确定」导出的到底是个什么东西。「拖动 + 缩放 → 导出 128×128」是纯几何，
也是这一版里最容易写错的地方：取景框、弹窗里那枚预览球、导出用的离屏画布，
三处各自缩放一次，任何一处抄错都只在图上看得出来，而那三张图平时都躺在弹窗里。
它把一个**非默认**的变换真的驱动出来（先缩到 2.2 倍，再往左上拖），点「确定」，
把存下来的那一份捞出来写成 `spike/out/ball-export.webp`（点「确定」之前的弹窗另存
`spike/out/ball-crop.png`，两张对着看：取景框里框住的，就是导出里该有的），
顺带断言它确实是一张 128×128 的 WebP、确实有内容。驱动用合成的 `PointerEvent`，窗口是隐藏的、
不抢焦点，系统光标一动不动。

```bash
npx electron spike/readme-assets.js
```

把上面 `preview.js` 抓到的界面原图排成 README 的那三张图，写进 `assets/`：

- `assets/banner.webp` 封面：项目名 + 一句话定位 + 一张真实的界面图
- `assets/features.webp` 三件能力：悬浮球 / 底板透明 / 三套主题
- `assets/shots.webp` 四张真实界面：界面骨架 / 起始页 / 系统设置 / 弹出面板

抓与排是两个脚本、两套验收标准：`preview.js` 管「界面对不对」，本脚本管
「版式好不好看」。界面图是**叠出来**的——窗口逐像素透明，界面自己只画顶栏与右栏，
网页画在另一个 `WebContentsView` 里，于是抓一张带透明通道的界面、再抓一张完整的
页面，按主进程给的同一个内容区矩形对齐，就是用户看到的那一帧。

> 版式的高度是**量出来的**：Windows 会把窗口高度卡在工作区里（任务栏那 48px 不给），
> 请求 1080 得到的是 1032，脚本会把真实画布尺寸打出来。按请求值排版、按实际值截图，
> 底下就会缺一条。图片编码用 Chromium 自己的 `canvas.toDataURL('image/webp')`，
> 不为此引入 sharp；编码完还会从**写盘后的 WebP** 回读一张缩小图 `verify-*.png`，
> 用来核对压缩之后是否还看得清（Read 工具看不了 WebP）。

另有一个一次性的探针 `spike/which-rules.js <主题> <选择器…>`：把命中了某个元素的
CSS 规则逐条列出来。作用域样式会让**子组件的根元素带上父组件的作用域属性**，
于是父组件里一条 `.某类名[data-v-父]` 的规则可能落到子组件头上——查这类串味，
逐条 `matches` 比盯着两个文件猜快得多。它只是诊断工具，验证仍以 `preview.js` 为准。
