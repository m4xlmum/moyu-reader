# 首页（起始页）

## Scope

`src/renderer/home.html` 与 `src/renderer/src/home/`。应用启动后的第一屏，也是所有「打开某个站点」动作的起点。窗口为 960×540 的 16:9 横屏，首页占据两条工具栏之间的正文区（约 960×458）。

## Visitor mode

**Operate。** 用户来这里是为了尽快开始读，不是为了被说服。界面的成功标准是他能在一秒内认出「这是在工作」，并在两秒内打开想读的东西。

## Audience, job, action

- **受众**：办公室 Windows 用户，屏幕随时可能被看到（走过来的同事，或正在进行的屏幕共享）。
- **任务**：在不离开工作界面的前提下开始阅读。
- **动作**：打开某个站点、继续上次的阅读、搜索。
- **内容**：站点来自 `我的站点` 与内置热门站点（`src/shared/presets.ts`，含 微信读书 / 晋江 / 起点 / 番茄 / 粉笔 / 力扣 等）；历史与书签来自本地存储。全部为真实数据，不虚构任何统计或评价。

## Constraints

- chrome 层覆盖整个窗口，正文区**必须可透明**：窗口透明时用户看到的是桌面，不是我们的背景色。
- **禁止毛玻璃**：`backdrop-filter` 在透明窗口背后模糊不了桌面，只能模糊自身内容。
- 正文区高度仅约 458px，且 16:9 下宽度充足、高度紧张——横向组织优先，纵向不做长滚动。
- 界面语言为简体中文。正文与关键标签不小于 12px。
- 透明度会常态处于 25%–45%，因此**关键控件的可辨识不能只靠颜色**，需要形状或位置上的区分。

## Chosen direction

**机读答题卡（OMR answer sheet）。** 把「今天想读的东西」排成一张待填涂的答题卡：每一行是一位站点，行首是题号与一个椭圆；已读过的涂满，当前打开的用红色登记标记。

这个隐喻不是装饰，它同时解决三个真实问题：一眼看过去是「学习资料」而非阅读器；分类天然对应答题卡的分大题（一、阅读 二、刷题 三、资讯 四、影音）；「涂满」正好是「已读」这个真实存在的状态。

**Memorable moment**：点开一个站点时，那一行的椭圆被铅笔涂满——用得着 2B 铅笔填涂的物理感，而不是一个勾选动画。

## Direction contract

**THESIS** — 首页是一张铺开的机读答题卡，而不是一块磁贴网格。品类默认（居中的搜索框 + 等距圆角磁贴 + 悬停上浮）被明确拒绝：那是一个「阅读器」的门面，而这里要的是「一份学习资料」。

**OWN-WORLD** — 只有两种墨：印刷黑 `#15171c` 与登记红 `#d1332e`，印在偏冷白的卡纸 `#f4f5f3` 上（不是暖米色——真实 OMR 卡纸在日光灯下是偏冷的）。层级全部靠线宽、字重与填涂承担，不引入第三种颜色，也不用灰色逃逸。字形用黑体承担标签与题号，正文用宋体承担说明文字——这是印刷表单的常规分工。组件语汇：带编号的粗框答题格、空心/涂满椭圆、红色登记条、手写信息框。把所有文字都拿掉后，剩下的应该是一张能被认出是答题卡的格线结构。

**STORY** — 用户首先认出「这是一份表格」而非「这是一个阅读器」，因此在有人走近时不产生解释成本；随后看清分大题与题号，明白自己的站点被按类别编排；最后点下某一行的椭圆，看着它被涂满。

**FIRST VIEWPORT** — 整屏就是一整张卡。最上方一条红底登记条贯穿左右，左端是卡的名称、右端是流水号。其下是头部区：左侧一块带粗框的手写信息框（会话/日期/已读计数），右侧是注意事项块，搜索框嵌在其中的第一行。再往下是答题区，占剩余全部高度，分左右两栏排布分大题（一、阅读 二、刷题 三、资讯 四、影音），每个大题内是编号的站点行：题号——站点名——椭圆。搜索框是第一动作，位于头部区左三分之一处。

**FORM** — 机读答题卡（OMR 表单）。在我按共鸣度排序的七项候选中位列第四。种子键 `784114e2`。由 declutter 得到的四处拔高：卡上每条印线必须承载信息（来自张拉整体）；头部信息框统辖其下所有行（来自球鞋档案墙）；状态读数钉在四角、中央留空给内容（来自摄录机 HUD）；硬性双墨纪律、拒绝灰色（来自池田亮司）。

**FINISH** — unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.

## Unresolved

- 椭圆「涂满」的判定口径（本次会话内打开过，还是历史累计）需在实现时定；倾向历史累计，因为它更稳定也更有意义。
- 卡片之外的深度定制（自定义站点分组）暂不做。
